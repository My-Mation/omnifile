TASK 2 — SHARED OCR SERVICE (engine for Tasks 3 & 4)
Goal: one on-device OCR service used by BOTH image editor and PDF
editor. Detects text blocks with position, estimated font size,
estimated color — everything downstream needs for font matching.

Build:
OcrService (domain service, pure Dart interface + ML Kit impl):
Input: image bytes (from image file OR rendered PDF page raster
at 150–300dpi, capped 2048px long edge)
Output model per text LINE: text, bounding box, and computed:
estimatedFontSize (see metrics below)
estimatedTextColor + estimatedBackgroundColor (see metrics)
weight guess (bold/regular via stroke-density heuristic)
alignment guess (left/center within block)
Group lines into blocks/paragraphs by line-gap heuristics.
Font-size estimation: fontSize ≈ bboxHeight × 0.72 (cap-height
heuristic); refine per-line using digit/uppercase content if
present. Expose as estimate — user can always adjust after.
Color estimation: decode region with image package; background
= median of pixels in 4px border ring around bbox; text color =
median of pixels inside bbox that differ from background by >
luminance threshold 40.
Weight heuristic: ratio of dark-pixel density inside glyph boxes;
> 0.42 → bold guess.
Low-confidence handling (blocks <0.5 confidence on >30% of page):
notice "Script may be unsupported — results may be poor".
Performance: run in background isolate via ML Kit's native async;
progress callback ("Reading page 3 of 12…"); cancelable.
Persistence rule: OCR results live ONLY in session memory unless
user saves the edited document (privacy anti-goal edit_v2 §8).
Acceptance checklist:
 OCR on photo of printed text: lines + boxes correct, sizes
within ±15% visually, colors plausible
 Works fully in airplane mode on FRESH install (bundled model)
 Scanned PDF page (rendered to raster) produces same results
 Cancel mid-run leaves no state; no crash on blank/noise image
