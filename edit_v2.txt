1. EDITING PHILOSOPHY & HARD RULES
1.1 The Golden Save Rule (NON-NEGOTIABLE)
The original file is read-only to the app, forever.
"Save" always creates a NEW document via SAF createDocument (default name: "<original> (edited).<ext>"), user can rename/choose location. If a file with the chosen name exists, append (2), (3)…
Session undo/redo stack per editor (minimum 50 steps). Undo history is lost on close (persistent edit history = v2.1, not now).
Before any lossy operation (export, flatten, format-strip), show a dialog listing exactly what will be lost. Never degrade silently.

1.2 Offline Editing Rule (NON-NEGOTIABLE)
OCR, format parsing, rendering, export: all 100% on-device.
FORBIDDEN: any cloud OCR API, any "online converter" fallback, any Firebase ML remote model. If a package requires a network round-trip at edit time, it is banned.
ML Kit base Latin text-recognition model is bundled in the APK (~4MB) — verify the build works in airplane mode from first launch. Script models beyond Latin (Chinese, Devanagari, etc.) are OUT OF SCOPE for v2 (they require on-demand download).

1.3 The Editing Reality Table (do NOT hallucinate beyond this)
State these capabilities EXACTLY as written in UI copy — no overpromising:

Format | Editing capability in v2 | Technique
TXT/MD/Code/CSV/JSON/XML/HTML(source) | FULL edit: insert/delete/replace, find&replace, syntax highlighting retained while editing | Editable text field (flutter_code_editor, readOnly:false)
Images (JPG/PNG/WEBP) | FULL edit: add text (font/size/color), freehand draw, crop, rotate, brightness/contrast; export | Canvas overlay editor
PDF | LAYER-BASED edit (see §3): text boxes, highlights, freehand ink, shapes, form fill; OCR-extract→edit→export-new-PDF. TRUE in-place text rewrite of existing PDF body text is IMPOSSIBLE — do not attempt, do not claim it in UI copy | Syncfusion PDF annotations + flatten on export
XLSX | FULL cell editing: values, add/delete rows/cols, basic styling (bold/align), multi-sheet | excel package (pure Dart read+write)
CSV | Full edit + table editor UI | Text engine + grid view
DOCX | TEXT-LEVEL edit of existing paragraphs & new paragraphs (inherit neighbor style). Formatting of untouched runs preserved. NOT a layout editor. | unzip → edit word/document.xml → rezip
PPTX | TEXT-LEVEL edit inside existing text frames only. No new slides/layouts. | unzip → edit slide XMLs → rezip
EPUB | OUT OF SCOPE v2 (read-only) | -

3. PDF EDITING (layer-based — the honest model)
3.1 Two edit modes, one editor screen
Mode A — ANNOTATE (visual layer on original pages):
- Text box tool: tap to place, drag to move, pinch font size, color picker (10 swatches), editable text; rendered as real PDF text
- Highlight tool: drag rectangles, yellow default, opacity 40%
- Ink tool: freehand pen, 3 widths, 8 colors, pressure-naive
- Shapes: rectangle/ellipse/arrow/line, stroke + optional fill
- Form fields: detect AcroForm fields (Syncfusion) → tap to fill text/checkbox/radio; flattened on save
- Eraser: tap annotation to delete; long-press any annotation → context popup: Edit / Style / Delete (ui_rules popup pattern)
- Undo/redo covers every annotation op

Mode B — EXTRACT & REWRITE (content editing):
- "Extract text" button → runs OCR (§4) + embedded-text extraction (use embedded text when present, OCR only for scanned pages)
- Produces an editable text document (per-page sections, headings heuristic from font size), opened in the Text editor
- "Export as PDF" from that editor → builds a NEW clean PDF (typed text, A4, simple heading/body styles). UI copy must say: "Creates a new, clean PDF from the extracted text" — NOT "edits your original"

3.2 Save/export
- "Save" (Mode A) → flattens annotations into a NEW PDF copy (Syncfusion flatten), never touches source
- Page ops allowed while annotating: rotate page, delete page, reorder (thumbnails strip, bottom sheet) — all via Syncfusion

3.3 PDF editor UI (extends ui_rules §9.6)
- Same viewer canvas + auto-hiding chrome; tool palette replaces overflow when Edit mode is on (pencil icon toggles Edit/View)
- Tool palette: bottom-docked, 72dp, horizontal scroll chips with icons: Select | Text | Highlight | Ink | Shape | Image stamp | Form | Pages. Selected chip = accent fill
- Annotation selected: floating popup card (Edit/Copy/Delete like the library popup spec §5.4)
- Zoom/pan unchanged while a tool is active; tool tap lands through transform (convert screen→page coords correctly — test at 3x zoom)

4. OCR PIPELINE (shared by PDF Mode B and Image text-editing)
- Engine: google_mlkit_text_recognition, Latin bundled model
- Input: PDF page render (150–300dpi raster, choose by page size cap 2048px) OR image file
- Output model: list of TextBlocks → lines → with bounding boxes + confidence; group into paragraphs by line gaps
- UX: full-screen progress ("Reading page 3 of 12…", cancelable), then a Review screen: page image with detected blocks boxed + extracted text beside it; user can fix, then insert into editor
- Language: attempt Latin first; if confidence <0.5 on >30% of blocks, show notice: "Text may be in an unsupported script — results may be poor"
- NEVER log or persist OCR text beyond the open document session (privacy rule) unless user saves
