1. DESIGN PHILOSOPHY
1.1 Core UI Principles (in priority order — when in doubt, the higher
number wins)

Invisible Chrome: The file IS the interface. Chrome (app bars, controls) must be minimal, dark-friendly, and disappear when not needed (fullscreen modes). When viewing content, the user should forget an app exists around it.
Instant Recognition: A user must identify a file's type in the recents list within 100ms — icons are the primary signal, always type-colored.
Thumb-First: All controls in the lower 40% of the screen where possible. Media controls, bottom sheets, and FABs follow this. One-handed use is the default assumption.
Calm, Not Boring: Monochrome surfaces with ONE accent color (teal). Depth comes from elevation and typography, never from color noise. No decorative elements that don't communicate state or action.
No Surprises: Every destructive action confirms. Every tap gives feedback within 50ms (ripple/haptic). Nothing moves unless the user caused it or it communicates loading progress.
Density When It Matters: File lists, archive contents, and hex views are information-dense. Settings and dialogs are comfortable. Match density to the task.
1.2 Anti-Patterns (STRICTLY FORBIDDEN)
Onboarding carousels, "welcome" screens, or tutorial overlays
Rating prompts anywhere in the UI
Banners, upsells, "go premium" hints (app is 100% free forever)
Colored large headers or gradient backgrounds on functional screens
Bottom navigation with more than 3 items
Hamburger menus for primary navigation (only 3 screens exist — use bottom bar)
Toasts for critical errors (use dialogs) or for success (use snackbar, max 1 visible)
Custom cursor/pointer effects on touch surfaces
Any animation longer than 400ms for state transitions
Drop shadows on flat surfaces inside viewers (content areas must be flat)

3.3 Text Rules
File names: MIDDLE TRUNCATION always (e.g., "myVeryLongFileName….pdf") in app bars; ellipsis-end in list tiles
Numbers (sizes, counts): use compact formatting — "1.2 MB" not "1258291 bytes"; "3 days ago" not full dates in lists (full date on tap via info dialog)
NEVER use ALL CAPS for anything except nothing. No caps. Not even buttons (Material 3 default is sentence case — keep it)
Min contrast: text.primary on any surface ≥ 7:1; text.secondary ≥ 4.5:1
4. SPACING, GRID & LAYOUT
4.1 Base Grid
Unit: 4dp. All spacing values MUST be multiples of 4: 4, 8, 12, 16, 20, 24, 32, 40, 48
Screen horizontal padding: 16dp (lists), 24dp (dialogs), 20dp (settings groups)
List item vertical padding: 12dp top/bottom (total tile height 72dp for two-line items)
Dialog content padding: 24dp all sides; 24dp between title and body; 8dp min between actions
4.2 Touch Targets
Absolute minimum: 48x48dp for ALL interactive elements — including icon buttons, video player controls, hex viewer rows
Spacing between adjacent touch targets: ≥ 8dp
Video player controls: 56dp hit areas with 40dp visual icons (hit area > visual)
4.3 Responsive Breakpoints
Width	Behavior
< 600dp	Phone: single column, standard layouts
600–839dp	Small tablet/foldable: Home recents becomes 2-column
           | grid; viewers center content with max-width 720dp            | and side gutters
≥ 840dp | Tablet/desktop: Home becomes 2-pane (recents left | 40%, preview hints right); dialogs max-width 560dp; | video player letterboxes with floating controls

4.4 Safe Areas
Respect ALL system insets (gesture nav bars, cutouts) via SafeArea
Video fullscreen: extend into system bars, controls padded by inset + 8dp
Never let tappable content sit within 24dp of a screen edge vertically

6. ICONOGRAPHY
Icon set: Material Symbols Rounded (match Material 3 shapes), outline weight for default, filled for selected/active states
Sizes: 24dp (app bars, list leading), 20dp (inline with text, buttons), 18dp (dense lists, chips), 48–96dp (empty states)
Every icon button MUST have a semantic label (tooltip + Semantics)
File-type icons in lists: use the semantic colors from 2.4, outlined style, with a small file-fold corner motif — implement ONE custom painter class that wraps any Material icon in a file shape (top-right folded corner), 40dp total

7.2 Motion Rules
Nothing animates on first frame of a screen (no entrance cascades in viewers — content appears immediately; only Home list may stagger at 30ms/item, max 8 items)
Loading states: indeterminate circular progress, 3dp stroke, accent color. NEVER block viewer content behind a full-screen loader — show loader in the app bar area + a centered 48dp indicator that disappears the instant first content renders
All animations interruptible mid-flight (no locked animations)
Reduce-motion: respect MediaQuery.disableAnimations — replace with opacity-only 100ms
