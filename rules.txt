PROJECT: OpenFile - Universal Offline File Viewer
VERSION: 1.0.0
TYPE: Flutter Mobile Application (Android-first)
============================================================================
1. PROJECT OVERVIEW & PHILOSOPHY
1.1 What This App Is
OpenFile is a completely OFFLINE, universal file opener and viewer for Android. It allows users to open, view, and interact with ANY file type on their device from a single app — PDFs, documents, code files, archives, images, videos, audio, and more.

1.2 Core Philosophy (NON-NEGOTIABLE RULES)
100% OFFLINE: The app must NEVER make any network request. No INTERNET permission in AndroidManifest.xml. No analytics. No telemetry. No tracking. No crash reporting that sends data externally.
100% FREE: No ads. No in-app purchases. No premium tier. No paywall. No feature gating behind payments.
PRIVACY FIRST: All file processing happens locally on the device. No file is ever uploaded anywhere. No user data is ever collected.
FAST & LIGHT: App size should stay under 50MB installed. Cold start to usable in under 2 seconds on a mid-range device. Opening any file under 10MB should feel instant.
RESPECTFUL UX: No dark patterns. No nag screens. No rating prompts that interrupt workflow. One-time permission requests with clear explanations only.
1.3 What This App Is NOT
NOT a file editor (viewing only, with minor exceptions noted below)
NOT a file manager (no browsing/copying/moving files — that's a different app; we only open files handed to us or picked by user)
NOT a converter (no format conversion in v1)
NOT a cloud sync tool
2. TARGET PLATFORM & REQUIREMENTS
Primary Platform: Android (API 24 / Android 7.0 minimum, target latest stable API)
Secondary (future): iOS — write code platform-agnostically where possible, but Android is the priority. Do not block on iOS issues.
Framework: Flutter (latest stable version), written in Dart with null safety enabled
Minimum Devices: Must run smoothly on devices with 2GB RAM. Test paths for low-memory devices.
Architectures: arm64-v8a, armeabi-v7a, x86_64
3. SUPPORTED FILE FORMATS (COMPLETE SPECIFICATION)
3.1 TIER 1 — Core Formats (Must work perfectly at launch)
Format	Extension(s)	Viewer Behavior
PDF	.pdf	Full paged viewer, swipe/scroll, pinch zoom, page indicator, jump-to-page, password-protected support
Text	.txt, .log, .md, .csv	Monospace-capable viewer, encoding auto-detection (UTF-8, UTF-16, Latin-1, ASCII), search within file, word wrap toggle
Markdown	.md	Rendered view (parsed markdown) with toggle to raw source
Images	.jpg, .jpeg, .png, .gif, .webp, .bmp, .heic	Full-screen viewer, pinch zoom, pan, rotate, EXIF data panel
Video	.mp4, .mkv, .avi, .mov, .webm, .3gp, .ts, .m4v	Full player with all controls (see section 5.4)
Audio	.mp3, .wav, .flac, .aac, .ogg, .m4a, .opus	Full player with waveform/seekbar (see section 5.4)
Archives	.zip	Browse contents as file list, tap to preview individual files inside, extract-all option
HTML	.html, .htm	Rendered via offline WebView with toggle to view source code
Code	.py, .js, .dart, .java, .kt, .c, .cpp, .h, .cs, .go, .rs, .rb, .php, .sh, .bat, .ps1, .sql, .xml, .json, .yml, .yaml, .toml, .ini, .cfg, .css	Syntax-highlighted viewer with line numbers, search, wrap toggle
3.2 TIER 2 — Secondary Formats (Must work, may degrade gracefully)
Format	Extension(s)	Viewer Behavior
Office (read-only)	.docx, .xlsx, .pptx	Best-effort rendering. If full rendering is not feasible with free/offline libraries, display: text content extraction for docx, sheet data grid for xlsx, slide text content for pptx, with a clear "limited preview" notice
Legacy Office	.doc, .xls, .ppt	Same approach as Tier 2 above; graceful degradation allowed
eBooks	.epub	Chapter-based reader with adjustable font size
JSON pretty	.json	Pretty-printed with collapsible tree view toggle
SVG	.svg	Rendered vector display with zoom
TAR/GZip	.tar, .gz, .tgz, .tar.gz	Same as ZIP handling
RAW text-ish	any unknown extension that begins with readable text	Auto-detect: if file appears to be mostly valid UTF-8 text, open in text viewer
3.3 TIER 3 — Fallback Behavior (Unknown/binary formats)
If file type is unrecognized OR cannot be rendered:
Attempt text detection (first 8KB check). If >90% printable characters, open in text viewer with a banner: "Opened as plain text"
Otherwise, show Hex View: offset column, hex bytes, ASCII gutter. Virtualized list (lazy-load chunks) so multi-GB files don't crash.
Always show a file info panel (name, size, MIME guess, modified date) in the unsupported screen with a "Share/Open with another app" button using the Android share intent.
